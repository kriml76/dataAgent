# 向量模型在 DataAgent 项目中的作用

## 概述

向量模型（Embedding Model）和向量数据库（VectorStore）是 DataAgent 项目实现 **RAG（Retrieval-Augmented Generation）** 架构的核心组件，主要用于知识检索和语义匹配，为 LLM 提供精准的上下文证据。

---

## 核心作用

### 1. 文本向量化

将业务知识、智能体知识等文本内容转换为数值向量（Embedding），存储到向量数据库中。

**实现位置**：`AiModelRegistry.java`

```java
public EmbeddingModel getEmbeddingModel() {
    ModelConfigDTO config = modelConfigDataService.getActiveConfigByType(ModelType.EMBEDDING);
    currentEmbeddingModel = modelFactory.createEmbeddingModel(config);
    return currentEmbeddingModel;
}
```

**关键特性**：
- 支持动态配置嵌入模型
- 懒加载 + 缓存机制
- DummyEmbeddingModel 兜底防崩

### 2. 语义相似度搜索

根据用户问题进行语义匹配，从向量库中召回最相关的文档作为证据。

**实现位置**：`AgentVectorStoreServiceImpl.java`

```java
public List<Document> search(AgentSearchRequest searchRequest) {
    Filter.Expression filter = dynamicFilterService.buildDynamicFilter(
        searchRequest.getAgentId(), searchRequest.getDocVectorType());
    return vectorStore.similaritySearch(hybridRequest.toVectorSearchRequest());
}
```

### 3. 证据召回（Evidence Recall）

在工作流中，`EvidenceRecallNode` 节点负责召回相关知识作为 LLM 回答的依据。

**实现位置**：`EvidenceRecallNode.java`

```java
private DocumentRetrievalResult retrieveDocuments(String agentId, String standaloneQuery) {
    // 获取业务知识文档
    List<Document> businessTermDocuments = vectorStoreService
        .getDocumentsForAgent(agentId, standaloneQuery, DocumentMetadataConstant.BUSINESS_TERM);
    
    // 获取智能体知识文档
    List<Document> agentKnowledgeDocuments = vectorStoreService
        .getDocumentsForAgent(agentId, standaloneQuery, DocumentMetadataConstant.AGENT_KNOWLEDGE);
    
    return new DocumentRetrievalResult(businessTermDocuments, agentKnowledgeDocuments, allDocuments);
}
```

| 列元数据 | `COLUMN` | 数据库列信息 | Schema 语义理解 |

## 检索策略

### 混合检索（Hybrid Search）

项目支持向量搜索和关键词搜索的组合，通过结果融合提升召回效果。

**实现位置**：`AbstractHybridRetrievalStrategy.java`

```java
public List<Document> retrieve(HybridSearchRequest request) {
    // 异步执行向量搜索
    CompletableFuture<List<Document>> vectorSearchFuture = CompletableFuture.supplyAsync(() -> 
        vectorStore.similaritySearch(request.toVectorSearchRequest()), executorService);
    
    // 异步执行关键词搜索
    CompletableFuture<List<Document>> keywordSearchFuture = CompletableFuture.supplyAsync(() -> 
        getDocumentsByKeywords(request), executorService);
    
    // 结果融合（Fusion）
    return fusionStrategy.fuseResults(request.getTopK(), vectorResults, keywordResults);
}
```

**检索流程**：

```
用户提问
    ↓
查询重写（LLM）
    ↓
┌───────────────┐     ┌─────────────────┐
│  向量搜索      │     │  关键词搜索      │
│  (语义匹配)    │     │  (全文检索)      │
└───────┬───────┘     └────────┬────────┘
        │                      │
        └──────────┬───────────┘
                   ↓
            结果融合（RRF/加权）
                   ↓
              证据构建
                   ↓
              LLM 回答
```

## 工作流程

### 端到端流程

```
1. 用户提问输入
        ↓
2. IntentRecognitionNode（意图识别）
        ↓
3. EvidenceRecallNode（证据召回）
        ├─ 查询重写（LLM）
        ├─ 向量检索（VectorStore）
        └─ 证据内容构建
        ↓
4. QueryEnhanceNode（查询增强）
        ↓
5. SchemaRecallNode（Schema 召回）
        ↓
6. 后续处理（SQL生成/执行等）
```

### 向量存储操作

| 操作 | 方法 | 说明 |
|-----|------|------|
| 添加文档 | `addDocuments()` | 将文档向量化后存入向量库 |
| 删除文档 | `deleteDocumentsByMetadata()` | 根据元数据过滤删除 |
| 搜索文档 | `search()` | 语义相似度搜索 |
| 检查存在 | `hasDocuments()` | 检查指定 agent 是否有文档 |

## 配置与扩展

### 默认配置

```yaml
spring:
  ai:
    vectorstore:
      type: simple  # 默认使用内存向量库
  alibaba:
    data-agent:
      vector-store:
        table-topk-limit: 10
        table-similarity-threshold: 0.2
        default-topk-limit: 8
        default-similarity-threshold: 0.4
        enable-hybrid-search: true  # 启用混合检索
```

### 支持的向量数据库

- **SimpleVectorStore**：内存向量库（默认）
- **Milvus**：专业向量数据库
- **PgVector**：PostgreSQL 向量扩展
- **Elasticsearch**：支持向量检索的全文搜索引擎

### 扩展方式

在 `pom.xml` 中引入对应的 Spring AI Boot Starter 依赖即可：

```xml
<!-- Milvus 示例 -->
<dependency>
    <groupId>org.springframework.ai</groupId>
    <artifactId>spring-ai-milvus-store-spring-boot-starter</artifactId>
</dependency>
```

## 关键设计特点

### 1. 动态代理模式

`EmbeddingModel` 通过动态代理实现模型热切换：

```java
@Bean
@Primary
public EmbeddingModel embeddingModel(AiModelRegistry registry) {
    TargetSource targetSource = new TargetSource() {
        @Override
        public Object getTarget() {
            // 每次方法调用，都去注册表拿最新的模型
            return registry.getEmbeddingModel();
        }
    };
    ProxyFactory proxyFactory = new ProxyFactory();
    proxyFactory.setTargetSource(targetSource);
    proxyFactory.addInterface(EmbeddingModel.class);
    return (EmbeddingModel) proxyFactory.getProxy();
}
```

### 2. 动态过滤器

支持根据业务规则动态构建检索过滤器：

```java
Filter.Expression filter = dynamicFilterService.buildDynamicFilter(
    searchRequest.getAgentId(), searchRequest.getDocVectorType());
```

### 3. 批量操作优化

支持大数据量的批量删除操作，处理 Milvus 等向量库的 topK 限制：

```java
private void batchDelDocumentsWithFilter(String filterExpression) {
    // 分批获取并删除，避免单次查询限制
    do {
        batch = vectorStore.similaritySearch(SearchRequest.builder()
            .query(DEFAULT)
            .filterExpression(filterExpression)
            .topK(batchDelTopkLimit)
            .build());
        // 删除批次文档
        vectorStore.delete(idsToDelete);
    } while (newDocumentsCount > 0);
}
```

## 总结

### 向量模型的核心价值

1. **语义理解**：将自然语言转换为机器可理解的向量表示
2. **知识检索**：实现精准的语义相似度匹配，为 LLM 提供上下文证据
3. **领域适配**：支持业务术语、知识库文档等多种知识类型的管理和检索
4. **检索增强**：结合混合检索策略，提升召回效果

### 架构优势

- **松耦合**：通过接口抽象，支持多种向量数据库无缝切换
- **可扩展**：支持热切换嵌入模型，无需重启服务
- **高性能**：异步并行检索 + 结果融合，提升响应速度
- **容错性**：DummyEmbeddingModel 兜底，保证服务启动稳定性
